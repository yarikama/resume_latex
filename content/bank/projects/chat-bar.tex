% INTERVIEW NOTES -- never on a page
%   - Why non-blocking on the client: the SFML loop runs at 60 Hz, and a blocking read
%     would freeze rendering whenever no packet arrives. Login stays blocking because it
%     waits on the user anyway.
%   - Why JSON instead of raw strings: typed fields (floats, names) in one packet, and two
%     packets merged in the stream fail to parse instead of being misread.
%   - Mode isolation: the client keeps handling map packets while a chat is open, so a
%     player who joins mid-chat appears at once.
